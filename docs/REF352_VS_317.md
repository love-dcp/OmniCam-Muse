对象：`F:\手机\OplusCamera.apk`（7.006.352，171,668,284 B）对 `work/camera317.apk`（7.006.317）。
两份都是 `com.oplus.camera versionCode=60000 / minSdk 35 / targetSdk 36`，AOSP R8 8.2.33 release。

**一句话结论：这是一次「补丁级」更新。两份 APK 结构完全相同（同 4584 个条目、同 35 个 dex、
同 35 dex 的类集合、`resources.arsc` 逐字节相同），真实代码改动只有两个方法的内部实现，
其余差异全是版本号/构建时间/构建 ID。模块的符号指纹与资源 id 不受影响。**

## 2. 两处真实改动

### 2.1 `em.t2.Jg(Ldb/f;)V` —— 夜景/高像素模式的预览决策守卫

`em.t2` 就是 `ProVideoModeAlt` 符号命中的那个模式类（模块里 `Mode.needBasicToneLut → em.t2.z2`）。
352 在该方法里新增一段：当选中的是 `highPixel` 且回调里 `db.f.e == null || db.f.q == 0`
（判定无效、不是夜景的决策）时直接丢弃并打日志：

```
"onPreviewDecisionResult, ignore invalid non-night decision, error: "
", featureType: "            // 日志 tag: CommonCapMode
```

即「高像素模式下收到无效的非夜景预览决策时不再照办」。是修 bug，不是改协议：
方法签名、字段、调用关系都没变（新增的只是字符串和一个 if 分支）。

### 2.2 `ka.l1.c/d(String,String)DataKey` —— retroCamera 的 DataKey 改成强类型

这个方法是按模式名把 `(模式, 名字)` 映射成 `p9.e.*` 常量键的工厂。352 里 `"retroCamera"`
那一支多了：

```
invoke-static {key, name, Integer.class}, Landroidx/activity/z;.j(...)   // DataKey.j(key,name,Class)
```

也就是 retroCamera 模式的键现在返回「带 Integer 类型的 DataKey」，其余五个模式
（professional / portrait / night / common / +默认）逐条指令一致。同样只影响 retroCamera。

## 3. 对模块的影响（明天适配要做的事）

结论：**不需要改 `symbols.json`，不需要改 native。**

理由：

1. 全部 35 个 dex 的类描述符集合一致 → R8 没有重排短名，`symbols.json` 里的类/方法/字段指纹
   所依赖的类名、成员名、参数形状、调用关系全部保持。
2. `resources.arsc` 逐字节相同 → 所有 `R$id` / `R$string` 数值不变，模块里用资源 id 的钩子
   （灵感构图卡片、面板控件、文案）不受影响。
3. 唯一改动的两个方法，模块只用到它们的「签名/存在性」：
   - `em.t2`（`ProVideoModeAlt`）与 `em.t2.z2`（`Mode.needBasicToneLut`）都还在，指纹不受影响；
   - `ka.l1` 在符号表里没有任何引用。
4. APK 里没有 `libAlgoInterface.so` / `libBasicTonePhoto*.so`：GR、大师色彩的 native 偏移
   （`gr_basictone.cpp` 里 `getSettingInt` 指纹表、`applyLmtPath` 结构偏移）取自 `/odm`，
   换 APK 不会动它们。
